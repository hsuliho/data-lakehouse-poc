# 3. 工作流 (Workflows & Pipelines)

## 1. 流水线设计总览

在数据湖仓系统中，稳定可靠的自动化工作流是数据流转的命脉。本系统的主体工作流由 **Dagster 声明式编排引擎** 驱动，以 UTC 日期（`dt=YYYY-MM-DD`）作为独立分区。每个分区的数据加载、SCD2 演进、dbt 建模及质量检查均可独立运行或回填。

为了展示日常增量流水线的全貌，我们通过以下时序与流程图来剖析数据从落地到消费的完整生命周期：

```mermaid
sequenceDiagram
    autonumber
    participant Landing as Landing 落地层
    participant Sensor as Dagster Sensor
    participant ODS as ODS / SCD2 脚本
    participant Dbt as dbt Spark 模型
    participant Check as Asset Checks (测试)

    Landing->>Sensor: 生成 _SUCCESS 标记文件
    Sensor->>ODS: 触发分区任务 (dt)
    Note over ODS: 执行 scripts/load.py & scd2.py
    ODS->>Dbt: 写入 Iceberg 原始表与维度表
    Note over Dbt: 执行 stg_ -> fact_ -> dws_ -> ads_
    Dbt->>Check: 执行 dbt 测试资产检查
    alt 测试通过 (容忍 Known Dirt)
        Check-->Sensor: 标记分区完成
    else 超额失败
        Check--->Sensor: 触发告警并中断
    end
```

## 2. 核心工作流步骤详解

### 步骤一：数据落地与 ODS 增量加载
- **触发**: 当新的业务日期批次数据到达 `landing/dt=YYYY-MM-DD/` 并且 `_SUCCESS` 标志位出现时，Dagster 传感器（Sensor）自动捕获并生成运行请求。
- **执行**: 调用 `scripts/load.py` 将 CSV 原始数据以追加（Append）方式写入 `ods.*_raw` 分区表，并更新当前快照状态 `ods.*`。

### 步骤二：缓慢变化维（SCD Type 2）演进
- **执行**: 调用 `scripts/scd2.py` 处理 `products` 和 `customers` 维度表。系统基于历史变更数据重新计算有效起止时间（`valid_from`, `valid_to`），确保历史事实关联的维度状态准确无误。

### 步骤三: dbt 建模与转换
- **执行**: `dagster-dbt` 动态解析 dbt 清单（manifest.json），按拓扑顺序依次执行：
  - **Staging 层**: 清洗异常字段。
  - **Fact 层**: 关联订单、客户、产品事实。
  - **DWS / ADS 层**: 计算每日营收及品类排名。

### 步骤四: 资产检查与容错机制 (Known Dirt)
- **质量校验**: 执行 dbt 测试作为 Dagster Asset Checks。
- **容错设计**: 为配合 POC 阶段的测试场景，系统内置了 `KNOWN_DIRT` 映射表（位于 `orchestration/definitions.py`）。对于因注入恶意污染数据而故意失败的测试（如特定违规价格或状态），系统允许在预设阈值内容忍，防止合法 POC 演练因可控污染中断；而对未知的异常违规则严格拦截报错。

## 3. AI 智能诊断代理工作流 (`agent`)

除了标准的数据管道，系统还引入了 LangGraph 智能代理。当系统出现异常或用户进行自然语言咨询时，代理将经历以下循环：
1. **意图识别与 Arm 挂载**: 根据用户请求选择对应的工作 Arm（如 `semantic`, `raw`, `diagnose`）。
2. **工具调用与速率平滑**: 调用 Trino 或 MetricFlow 工具获取底层证据，同时内置 `_throttle` 与指数退避重试机制，完美适应 Gemini 免费层的速率限制。
3. **人类干遇 (Human-in-the-loop)**: 遇到歧义或需要澄清时，通过 `interrupt` 安全暂停，等待用户输入后继续。
